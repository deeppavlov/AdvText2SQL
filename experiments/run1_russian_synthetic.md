## Главный вывод

**Дообучение НЕ дало прироста.** Лучшая FT-модель (gpt-4.1, 22.6%) едва выше baseline
(19.4%), половина моделей — заметно хуже. Это не шум, а системная проблема.

## Три причины (по убыванию важности)

### 1. Языковой рассинхрон train ≠ test 🔴 главная
- Обучали на **русских** вопросах: `"Какое минимальное значение id в таблице sets?"`
- Тестировали на **английских** (BIRD): `"What is the unique id of the set...?"`

Модель специализировалась на «русский → SQL», тест — «английский → SQL».
FT увёл модель в русский домен → на английском тесте не лучше базовой.
Подтверждение: FT-модели пишут SQL-комментарии по-русски даже на английский вопрос.

**Урок**: инвариант train==inference должен совпадать не только по схеме БД,
но и по **языку/стилю запросов**.

### 2. Коллапс в повторы (переобучение) 🔴
`exp_gpt41_mini` и `exp_gpt41_nano` на сложных вопросах зацикливаются:
```sql
WHERE "name" IN ('Dandan','Dandan','Dandan', ... ×80)
text LIKE '%desencantar%' OR text LIKE '%desencantar%' OR ... ×50
```
Признак переобучения на малом/однообразном синтетическом наборе.
Сильнее всего бьёт по nano/mini (беднее синтетика) — отсюда их 6.5% и 16.1%.

### 3. Не передавали evidence (структурный потолок) 🟡
BIRD-вопросы опираются на подсказки `evidence`:
```
Вопрос: "foil non-powerful"
Gold:   WHERE cardKingdomId IS NULL OR cardKingdomFoilId IS NULL
```
«non-powerful» = «нет cardKingdom id» — знание из `evidence`, которое мы не подавали.
Без него потолок ~20% для ВСЕХ моделей, включая baseline.

## Что дальше (эксперимент №2)

1. Генерировать синтетику **на двух языках**: 500 RU + 500 EN на каждый генератор.
2. Выделить **валидационный сет** из валидных Q-SQL пар.
3. Передавать **evidence** в инференсе (снять структурный потолок).
4. Тестировать на BIRD (английский) — там FT на EN-синтетике должен дать прирост.
5. Упростить пайплайн: один скрипт на этап, согласованные имена папок/файлов.
