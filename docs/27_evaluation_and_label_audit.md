# AUD-007/008: оценщики и проверка меток — 13.11.2026

Исправлены базовые пути оценки и импорта меток. Проверка источников показала:
**актуальные 1 594 наблюдения v2 не требуют изменения меток**.
Исторические ответы, отчёты, датасеты, модели и манифесты сохранены.

## Исправления

| Пункт | Что изменилось |
| --- | --- |
| AUD-007 | Базовый Ambrosia evaluator и исследовательский evaluator используют общий `adv_text2sql.evaluation.ambrosia_report`: `error` всегда неверен; пустые ответы, чужие/недостающие ID и дубли эталонных ID отклоняются |
| AUD-007 | Базовый predictor останавливается до генерации при отсутствии нужных tools вместо пропуска вопросов. Legacy-экспорт Ambrosia требует полного покрытия и использует строгую правильность |
| AUD-007 | Launcher принимает только `--evaluation-policy strict`; ошибочная ручная сводка больше не перезаписывает строгие F1/recall. `legacy_accuracy` остаётся диагностическим полем |
| AUD-008 | Базовый BIRD evaluator различает этапы reference/prediction/connection. Сбой инфраструктуры, неизвестная ошибка или ошибка эталона останавливает оценку без отрицательной метки; ошибка SQL prediction остаётся неуспехом |
| AUD-008 | Новые записи ошибок содержат безопасные поля `execution_stage`, `failure_kind`, `sqlstate`, `error_type`; полный текст исключения с параметрами подключения не сохраняется |
| AUD-008 | При импорте архивов одного совпадения SQL недостаточно: проверяются SQLSTATE либо известный класс драйвера. Инфраструктура/неизвестная причина дают `observed=false`, `correct=null`; legacy BIRD-экспорт такие ошибки отклоняет |
| AUD-008 | Prompt evaluator и импорт v2 используют тот же классификатор SQLSTATE: отмена/таймаут запроса, нехватка ресурсов и прав не становятся отрицательными метками |

Неизвестная причина не объявляется подтверждённым обрывом соединения. Исторические
известные ошибки SQL вроде `UndefinedColumn` и `WindowingError` остаются ошибками
модели, когда сохранённый SQL однозначно относится к prediction.

## Проверка сохранённых меток

Скрипт [`audit_evaluation_labels.py`](../scripts/audit_evaluation_labels.py) проверяет
хеши источников, повторно классифицирует наблюдения и сравнивает их с метками.
Никаких SQL, SSH, LLM или загрузки моделей при этом нет.

| Датасет | Проверено наблюдений | Изменённых меток | Неизвестных результатов после проверки |
| --- | ---: | ---: | ---: |
| Configuration utility, 28.10 | 1 872 | **0** | 0 |
| Multilabel v1, 29.10 | 17 784 | **0** | 1, уже исключён ранее |
| Configuration utility v2, 09.11 | 1 594 | **0** | 0 |

Это числа «вопрос × конфигурация», не независимых вопросов; источники датасетов
пересекаются. Единственный уже исключённый результат — пустой ответ FEAT_25
на Ambrosia №278. Новая очередь восстановления по AUD-007/008 **пуста**.

В проверенных уникальных Ambrosia-папках есть **21 ответ `error` на однозначных
вопросах**, который старая метрика могла засчитать как успех. Формальные датасеты
классификатора уже оценивали эти ответы строго, поэтому метки не изменились.
Это не 21 новая ошибка разметки v2.

Результаты: [`impact.json`](../research_results/evaluation_labels_audit_20261113/impact.json)
и [`reviewed_observations.jsonl`](../research_results/evaluation_labels_audit_20261113/reviewed_observations.jsonl).
Сохранены SHA данных и кода проверки. Промежуточные отчёты перенесены в локальную
`.cache/evaluation-label-audit-drafts-20261113/`.

Проверка относится к трём перечисленным формальным датасетам. Старые
`feature_labels*.json`, другие ветки и результаты Ильи не объявляются
переразмеченными. Остальные замечания аудита, включая преобразования SQL,
checkpoint identity и независимость holdout, остаются отдельными задачами.

## Проверки кода

**135 тестов и 41 subtest прошли**, включая 17 новых тестов AUD-007/008,
50 тестов безопасности, configuration/multilabel builders, сбор v2, prompt pilot
и комбинации. Ruff на изменённых модулях прошёл. Проверки выполнялись локально
с подменённой БД, без API/SSH; pytest взят из локального кеша, временные файлы —
в `.cache/`. Полный набор тестов проекта и реальная PostgreSQL не проверялись.

## Следующие действия

1. Массовая переразметка актуального v2 и повтор его 1 594 оценок по этим двум
   дефектам **не нужны**: метки совпали. Обучение на тех же данных исправлениями
   оценщика не улучшается автоматически.
2. Перед новыми платными запусками подготовить отдельную версию протокола с
   текущими исходниками и `src/adv_text2sql/evaluation.py`, а также модулями
   безопасности отчёта 27. Старые SHA не заменять и checkpoints не обнулять.
3. Продолжить подготовленные повторы train и расширение на 111 структурно
   согласованных вопросах Ambrosia. Новые метки экспортировать отдельной версией,
   сохранив DB/family-разделение; затем переобучить голову и проверить на dev.

Новых платных запусков и обучения в рамках исправлений **не было**.
