**05.11.2026: первый и исправленный guardfix-поиски завершены. В исправленном
поиске все четыре предложения прошли guard; два новых промпта на inner-val дали
16/24 против исходных 17/24. Сохраняем исходный текст, dev-подтверждение не требуется.**
Следующий эксперимент после [статического гибрида](18_full_static_hybrid.md).
В рамках ограниченного SQL-only пилота улучшения не получено; итог ниже.
**Весь этап Phase 1.5 остаётся открытым:** MIPROv2, TextGrad, few-shot и
оптимизация детектора ещё не проверены; общий отрицательный вывод преждевременен.

## Что проверяем

GEPA оптимизирует один текстовый slot: правила генерации SQL. Сохраняем
исходный генератор, системную схему, вопрос/evidence, указание PostgreSQL,
SQL-only контракт, детектор неоднозначности и фиксированную маску **14+32**.
Исходная инструкция — seed; её подстановка побайтно воспроизводит исходный
SQL-шаблон и сообщения настоящего генератора в офлайн-тесте.

Используется официальный [GEPAAdapter](https://github.com/gepa-ai/gepa/blob/v0.0.27/src/gepa/core/adapter.py)
с `evaluate` и `make_reflective_dataset`, а поиск выполняет
[`gepa.optimize`](https://github.com/gepa-ai/gepa/blob/v0.0.27/src/gepa/api.py).
Версия **0.0.27** закреплена, исходники пакета проверяются SHA-256. Пакет установлен
без дополнительных зависимостей в `.cache/prompt_optimizer/`; исходное `.venv`,
`pyproject.toml` и `uv.lock` не изменялись. MIPROv2, TextGrad и отдельная
оптимизация ambiguity-промпта остаются последующими экспериментами.

Task model — прежний `deepseek-flash`, заявленная версия
`DeepSeek-V4.1-Flash-1017`. Teacher по умолчанию использует ту же модель и
`.env.deepseek`. Пилот проверяет интеграцию и пользу рефлексии при таком teacher;
эффект более сильного teacher этим запуском не измеряется. Смена модели или
протокола требует отдельной папки и нового манифеста.

## Данные и защита от утечки

| Часть | Вопросы | БД | Роль |
| --- | ---: | --- | --- |
| Optimization fit, только прежний BIRD train | 24 | codebase_community, student_club | Минибатчи, трассы и reference SQL для teacher |
| Внутренняя validation, только прежний BIRD train | 24 | superhero, toxicology | Выбор кандидатов GEPA, без передачи feedback teacher |
| Внешний dev BIRD | 55 | Прежние две dev-БД | Только последующее сравнение |
| Внешний dev Ambrosia | 46 | Прежние 15 dev-БД | Проверка побочных эффектов, Accuracy/F1 |

Взято по 12 вопросов каждой обучающей БД: детерминированный отбор с seed 42 и
распределением по сложности, без просмотра правильности ответов. Fit и inner
validation разделены по БД; внешние dev-БД также не пересекаются с ними.
Это маленький пилот на уже просмотренных данных, не независимый финальный test.

Task model получает только прежние вопрос/evidence, схему и инструкции.
Gold SQL доступен evaluator и teacher **только для fit**. Adapter отклоняет
чужие/изменённые вопросы; inner-val/dev-трассы запрещены в reflection feedback.
Проверяется отсутствие явного копирования обучающих вопросов, названий БД,
SQL-примеров и изменения защищённых slots в новой инструкции. Эти ограничения
не заменяют проверку переноса на новые БД.

Перед любыми платными запросами фазы проверяются живые схемы и исполнение всех
выбранных BIRD-эталонов в read-only транзакциях. Несоответствие или неисполняемый
gold останавливает фазу. BIRD оценивается по совпадению множеств результатов
с прежним транспайлером SQLite→PostgreSQL и нормализацией массивов/JSON.
Ошибка SQL модели получает score 0; потеря связи с БД останавливает выполнение
до записи ложной отрицательной метки. Ambrosia использует прежнюю strict-оценку
неоднозначности, а не SQL EX.

## Две вручную запускаемые фазы

| Фаза | Что происходит | Предельный бюджет |
| --- | --- | --- |
| `search` | GEPA Pareto, минибатчи 3, без merge; меняются только SQL-правила на 14+32 | 160 различных оценок «кандидат × вопрос», 400 task-вызовов, 4 teacher-вызова, 2 млн токенов, 90 минут активного времени |
| `confirm` | Исходный/выбранный промпт × baseline/14+32 на внешнем dev | 404 оценки, 1 000 task-вызовов, 0 teacher-вызовов, 4 млн токенов, 120 минут активного времени |

Это верхние границы, не обещанный расход. У одного вопроса обычно есть отдельно
checker и SQL-вызов. Максимальный output: task 4 096, teacher 2 048 токенов.
Скрытые SDK-retry отключены; transport boundary прекращает фазу при первом
сбое после одного HTTP-запроса. Алгоритм обработки вопроса и фичи не расширены
repair/voting-вызовами.

Перед запросом сохраняется резерв стоимости по консервативной оценке входа
(UTF-8 bytes + 1 024 служебных токена) и максимальному output. По ответу резерв
заменяется фактическим usage. Неопределённый расход неуспешного запроса остаётся
зарезервированным; повторный ручной запуск не сбрасывает бюджет. При неожиданном
usage или превышении оценки выполнение останавливается для разбора. Это
контроль токенов/вызовов, не точный долларовый лимит аккаунта.

Завершённые ответы кэшируются по фазе, инструкции, маске, бенчмарку и ID вопроса.
Возобновление не генерирует их заново; незавершённый вопрос можно повторить,
сохраняя расходы предыдущей попытки. Кэш фиксирует первый измеренный результат,
поэтому этот пилот не измеряет вариативность ответов повторными генерациями.

Выбирается кандидат с лучшим EX на **полной inner-val**. При равенстве сохраняется
seed; далее учитываются меньшая длина и SHA. Неполностью оценённые кандидаты не
могут победить. Если выигрыша нет, остаётся seed и платная `confirm` не требуется.
Остановка по исчерпанному штатному бюджету допускает выбор среди полностью
оценённых кандидатов; сбой API/учёта расхода не считается успешным завершением.

## Команды первого запуска v1 (уже завершён)

Для следующего поиска используйте guardfix-команду в итоговом разделе ниже.

Из корня проекта в PowerShell. Сначала можно проверить параметры без SSH/БД/API:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_prompt_pilot.ps1 --dry-run
```

**Первый платный запуск — только поиск:**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_prompt_pilot.ps1 --phase search
```

SSH поднимается существующим `start_tunnel.sh`. Ориентир для поиска — порядка
30–60 минут при прежней скорости API; фактическая длительность зависит от числа
принятых кандидатов, времени SQL и остановки по лимитам. Повтор той же команды
продолжает незавершённую фазу с прежними кэшем и бюджетом.

После разбора `selection.json` и отчёта — **отдельная ручная команда**:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_prompt_pilot.ps1 --phase confirm
```

Она сравнит четыре условия на одинаковом dev. Если выбран исходный seed,
платные вызовы не начнутся. Уже завершённая фаза также не обращается к БД/API.
Рабочие промпты автоматически не заменяются, метки классификатора не меняются.

Офлайн-наблюдение и пересборка отчёта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_prompt_pilot.ps1 --status
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_prompt_pilot.ps1 --report
```

Для другой машины пакет устанавливается отдельно без изменения `.venv`:

```powershell
.venv\Scripts\python.exe -m pip install --no-deps --target .cache/prompt_optimizer -r requirements-prompt-optimization.txt
```

## Первый запуск: результаты и исправление guard

Ни один новый кандидат не дошёл до полного оценивания inner-val, поэтому
запись «selected 17/24; seed 17/24» означает выбор того же исходного текста,
а не равенство двух независимо проверенных промптов. Внешний dev не оценивался.

### Исправленный запуск guardfix (уже завершён)

Новая версия `scripts/prompt_pilot_guardfix.py` применяет SQLGlot к отдельным
SQL-фрагментам строк вместо поиска ключевых слов через весь текст. Все четыре
реальных предложения v1 проходят новую проверку; настоящие SQL-примеры,
изменения slots, копирование вопросов и имён обучающих БД по-прежнему блокируются.
Версии entrypoint несовместимы, чтобы прежняя команда не выполнила новый манифест
с прежней ошибочной проверкой.

Данные, seed, модели и лимиты те же. Это **новый ограниченный поиск с новым
бюджетом**, не продолжение v1 и не перенос его отрицательных оценок. Контроль
измеряется заново. Общий расход двух экспериментов нужно суммировать отдельно;
первоначальные 194 269 токенов не стираются и не входят в новый счётчик.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_prompt_pilot_guardfix.ps1 --phase search
```

Папка: `research_results/prompt_optimization_20261105_guardfix/`.
Ориентир по измеренной скорости v1 — **10–25 минут**, если соединение стабильно;
принятые кандидаты потребуют дополнительных полных inner-val оценок. Жёсткий
лимит остаётся 90 минут активного времени, 160 оценок, 400 task- и 4 teacher-вызова,
2 млн токенов. Исходный код, отчёты и журналы v1 не изменяются; их SHA закреплены
в `correction_of` нового манифеста.

Офлайн-статус:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_prompt_pilot_guardfix.ps1 --status
```

Подтверждение на dev пока не нужно. После исправленного поиска, если выбран
улучшенный текст, используем тот же guardfix-launcher с `--phase confirm`.
Если сохранён seed, платного dev-подтверждения не будет. Рабочие промпты и
разметка классификатора пока остаются прежними.

Проверка исправления: **27 тестов пилота прошли**, включая шесть новых проверок
реальных предложений, сохранения защит и изоляции версии. Старые исходники v1
не редактировались.

## Итог исправленного поиска

Guardfix завершён **05.11.2026 в 10:35 МСК**, активное время **13 мин 43 с**.
Манифест, выбранный профиль и provenance v1 прошли проверку. Все четыре ответа
teacher проверены новой проверкой инструкций, ложных отклонений нет.

| Кандидат | Минибатч fit: seed → кандидат | Полная inner-val | Accuracy | Изменение к seed |
| --- | --- | ---: | ---: | ---: |
| Исходный seed | — | **17/24** | **70,83%** | — |
| Предложение 1 | 1/3 → 1/3 | Не запускалась | — | Нет строгого улучшения на минибатче |
| Предложение 2 | 1/3 → 2/3 | 16/24 | 66,67% | −4,17 п.п. |
| Предложение 3 | 1/3 → 2/3 | 16/24 | 66,67% | −4,17 п.п. |
| Предложение 4 | 2/3 → 2/3 | Не запускалась | — | Нет строгого улучшения на минибатче |

У каждого полностью проверенного нового кандидата относительно seed:
**0 исправленных / 1 ухудшенный ответ**. Оба потеряли вопрос BIRD ID 744.
По superhero seed решает 10/12, новые — 9/12; по toxicology у всех 7/12.
Выигрыш на трёх fit-вопросах не перенёсся на другие обучающие БД inner-val.
Поэтому выбран точно тот же seed, его текст и fingerprint проверены.

| Расход / исправность guardfix | Значение |
| --- | ---: |
| Завершённые различные оценки кандидат/вопрос | 96 |
| Task / teacher вызовы | 192 / 4 |
| Всего токенов | **399 905** |
| Токены task / teacher | 370 462 / 29 443 |
| Входные / выходные токены | 373 923 / 25 982 |
| Незакрытые резервы / transport_events | 0 / 0 |
| Ошибки SQL модели | 1, fit ID 1339, PostgreSQL 42883 UndefinedFunction |
| Совокупный расход v1 + guardfix | **594 174 токена, 284 записанных вызова** |

Один SQL failure учтён как ноль на fit, это не потеря связи и не проблема gold.
Внешний dev не оценивался и teacher его не получал. В машинном отчёте dev-ячейки
остаются `pending`, но **они не являются оставшейся обязательной очередью**:
нового выбранного промпта нет, поэтому `confirm` по предусмотренному правилу
не начнёт платные вызовы.

Ограниченный пилот закрываем с отрицательным результатом: **четыре рефлексии
тем же DeepSeek и оптимизация только SQL-правил на 14+32 не улучшили inner-val**.
Это не доказательство бесполезности GEPA в целом: здесь мало БД/вопросов,
малый бюджет, один проход, не исследованы другой teacher, few-shot и отдельный
ambiguity-slot. Продолжение такого поиска требует отдельного протокола, а не
автоматического увеличения лимитов после просмотра результата.

Исходные промпты, статические профили и метки классификатора остаются прежними.
Следующий основной шаг — [сравнительная серия оптимизаторов и few-shot](15_prompt_optimization_plan.md#ближайшая-сравнительная-серия),
а не немедленный переход к переобучению классификатора. После фиксации prompt
profile обновляем датасет полезности по проверенным комбинациям и train/dev-повторам,
учитываем исключённые вопросы и неизвестность непроверенных сочетаний.
Перенос текущих large/test-результатов в независимый тест не допускается;
для итогового подтверждения нужны новые данные.
Итог с хешами исходных файлов сохранён в `pilot_conclusion.json` guardfix-папки.
Его рекомендация `next_step` о переходе к классификатору заменена уточнённым
планом выше; исходный артефакт пилота сохранён без изменений.
