# Phase 2, шаги 2–3 — классификатор и интеграция с DeepSeek

**29.10.2026: первая модель реализована, обучена и проверена с DeepSeek на 100 test-вопросах.**
Прогон завершён: BIRD 18/55 (32,73%), Ambrosia 37/45 (82,22%), F1 Ambrosia 55,56%.
Лучший статический гибрид не превзойдён. Подробности —
[сравнение завершённого прогона](../research_results/multilabel_deepseek_test_20261029/comparison.md).
LoRA не обучалась — работа Ильи остаётся отдельным компонентом генератора.

## Реализация

| Часть | Файл |
| --- | --- |
| Энкодер, schema scaler, masked loss, голова, ограничения | [multilabel_classifier.py](../src/adv_text2sql/mcp_servers/text2sql_tool/src/multilabel_classifier.py) |
| Применение маски в генераторе | [multilabel_generator.py](../src/adv_text2sql/mcp_servers/text2sql_tool/src/multilabel_generator.py) |
| Загрузка и проверка энкодера | [prepare_classifier_encoder.py](../scripts/prepare_classifier_encoder.py) |
| Обучение и отдельная оценка | [train_multilabel_classifier.py](../scripts/train_multilabel_classifier.py) |
| Сравнение live-прогона с контролями | [classifier_benchmark.py](../scripts/classifier_benchmark.py) |
| Ручной запуск с SSH | [run_multilabel_deepseek.ps1](../local/run_multilabel_deepseek.ps1) |
| Артефакты | [model.json](../research_results/multilabel_classifier_deepseek_20261029/model.json), `head.npz`, `training.json`, `threshold_selection.json`, `evaluation.json`, `predictions.json` |

```text
question + evidence → замороженный MiniLM → 384 признака
schema_stats → log1p → нормализация по train → 6 признаков
                        ↓
                 Linear(390 → 16)
                        ↓
          sigmoid → порог → ограничения → FEAT-маска
```

Использован компактный английский
[sentence-transformers/all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2).
Его model card описывает 384-мерный выход, усреднение с учётом attention mask и
L2-нормализацию. Здесь энкодер работает в `eval()` / `inference_mode()`, все
`requires_grad=false`; ограничение входа — 256 токенов. Длинный текст обрезается
токенизатором. Вход формируется одинаково при обучении и применении:
`Question: ...\nEvidence: ...`.

Веса загружены в локальный игнорируемый `.cache/classifier/minilm/`, а версия
закреплена SHA **1110a243fdf4706b3f48f1d95db1a4f5529b4d41** и SHA-256 каждого
файла. Во время обучения и инференса загрузка из сети запрещена через
`local_files_only=True`, произвольный remote code выключен. Head хранится в
NPZ без pickle; проверяются хеш, формы массивов и значения.

| Параметр | Значение |
| --- | --- |
| Обучаемых параметров энкодера | **0** |
| Обучаемых параметров головы | **6 256** |
| Выходы | 1, 2, 12, 13, 14, 15, 16, 20, 21, 23, 25, 28, 29, 30, 32, 35 |
| Схема | Число таблиц, колонок, text/numeric/temporal/boolean колонок |
| Преобразование схемы | log1p, mean/std только на train; постоянные признаки имеют scale=1 |
| Train / dev | 267 / 101 вопрос, исходные DB/family splits |
| Seed | 42; CPU, детерминированные операции |
| Оптимизатор | AdamW, lr=0,01, weight_decay=0,01; вся train-матрица на шаг |
| Loss | Masked BCEWithLogits; targets — benefit относительно all-false baseline |
| Веса редких классов | sqrt(negative/positive), максимум 20; только train |
| Checkpoint | Минимальный dev weighted loss; лучший epoch **21**, остановка после epoch **51** |
| Порог | Из фиксированной сетки 0,2 / 0,35 / 0,5 / 0,65 / 0,8 по constrained micro-F1 на dev |
| Выбранный порог | **0,35** |
| Бюджет маски | Не более **3** фичей; допустима пустая маска |
| Библиотеки | torch 2.15.0+cpu, transformers 4.57.6; остальные версии в model.json |

Маска исключает отсутствующие/невалидные метки из суммы и знаменателя loss.
NaN на замаскированных позициях заменяются только внутри вычисления loss;
в датасете пропуски сохраняются. Их градиент равен нулю. Ничья имеет benefit=0
смыслом «нет наблюдаемого улучшения», как зафиксировано в [датасете](07_multilabel_dataset.md).

Test не входит в обучение, нормализацию, early stopping или выбор порога.
Модель заморожена в `model.json` до отдельной команды `evaluate`. Это не меняет
того, что сам test уже просматривался в Phase 1 и остаётся ретроспективным.

## Оценка предсказания меток

**Следующие числа не являются Accuracy SQL или F1 неоднозначности Ambrosia.**
Это качество предсказания слабых меток полезности одиночных фичей. Для
произвольных выбранных комбинаций сохранённых downstream-ответов нет.

| Часть | Подход | Micro-F1 меток | Hamming loss | Среднее число выбранных фичей |
| --- | --- | ---: | ---: | ---: |
| Train | Классификатор | 27,72% | 0,0623 | 0,94 |
| Dev | Классификатор | 10,86% | 0,1219 | 1,62 |
| Test | Классификатор | **6,67%** | 0,0525 | 0,50 |
| Test | Все фичи выключены | 0,00% | **0,0250** | 0,00 |
| Test | Постоянная маска 14+32+35 | 8,24% | 0,1950 | 3,00 |

Первая модель слабо переносится на test. Hamming loss предпочитает все нули из-за
доли положительных меток около 2,86%; одной этой метрики недостаточно. На test
непустая маска выбрана для **33/100** вопросов. Это технический результат первой
модели, а не доказательство улучшения системы. После оценки test модель и пороги
не подстраивались.

Сырые sigmoid-значения не калиброваны как вероятность реального причинного
улучшения. Одиночные слабые метки не гарантируют пользу комбинаций; некоторые
фичи имеют лишь 1–3 положительных примера в train. Следующий live-прогон нужен
для проверки, а не для подтверждения заранее предполагаемого прироста.

## Выполненный downstream-прогон — 29.10.2026

| Подход | BIRD, верно / 55 | BIRD Accuracy | Ambrosia, верно / 45 | Ambrosia Accuracy | Ambrosia F1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Все фичи false | 17 | 30,91% | 34 | 75,56% | 15,38% |
| Постоянно 35 | 19 | 34,55% | 34 | 75,56% | 15,38% |
| Постоянно 14+32+35 | **22** | **40,00%** | **39** | **86,67%** | **66,67%** |
| Multilabel | 18 | 32,73% | 37 | 82,22% | 55,56% |

Это 55/45 отложенных вопросов, **не полные large-наборы**. Сравнение использует
одинаковые ID; контроли исторические. Все реальные маски совпали с заранее
сохранёнными предсказаниями классификатора. Generation/provider errors и пустых
ответов нет; две ошибки синтаксиса SQL на BIRD (180, 1482) учтены как неверные.

На BIRD выбрана пустая маска в 50/55 случаев. Единственное улучшение относительно
baseline (ID 102) тоже получено без фичей, поэтому его нельзя приписывать выбору
фичей. На Ambrosia маска непуста в 28/45 случаях; четыре улучшения относительно
baseline получены с 32 или 21+32, одна потеря — при пустой маске.

Классификатор ни разу не выбрал 14 или 35 на test, и проверенная комбинация
14+32+35 не воспроизведена. Слабые метки одиночных флагов и небольшой train не
гарантируют качество совместного решения. Это ограничение постановки/обобщения,
а не обнаруженное расхождение между маской модели и выполненными флагами.

Время: **16 мин 11 с**, расход: **182 904 токена** с двумя probe, **199** записанных
успешных вызовов. По снимкам баланса потрачено **0,03 USD**. Точных затрат
исторических контролей на этих test ID нет; экономия относительно гибрида не доказана.

Основная опора остаётся статический 14+32+35. Следующую версию разрабатывать на
train/dev, учитывая взаимодействия и контекст меток. Полный прогон текущей версии
не приоритетен; для итоговой проверки следующей версии нужны новые вопросы/БД.

## Ограничения масок и подготовка контекста

Выход ограничен 16 допустимыми головами. Флаги, исключённые в датасете из-за
зависимостей, инфраструктуры и состояния кэша, не включаются автоматически.
Пустая маска означает настоящий all-false baseline, а не скрытый FEAT_35.

Заранее зафиксированы консервативные ограничения известных перекрытий:
14/29, 20/28 и 12/32 не выбираются вместе. В конфликте сохраняется фича с более
высоким score. У 14/29 перекрытие зависит от ветки сложности, а у 12/32 возможно
отличие на fallback после ошибки; это политика ограничения первого эксперимента,
не утверждение, что все такие сочетания всегда идентичны. Затем действует бюджет
трёх фичей.

Структурные признаки БД собираются бесплатно через TSV. Это предварительное
извлечение не означает, что TSV обязательно попадёт в промпт генерации: при
выключенном 35 используется исходный light-формат. Схема/связи/статистики/MinHash/
описания готовятся лениво только для реально выбранных build-фичей 1/2/21/23/35
и кэшируются внутри БД по этому набору. FEAT_23 может делать дополнительные
платные вызовы при подготовке описаний.

Каждая комбинация имеет изолированный модуль с собственными константами,
а каждый вопрос — свой экземпляр генератора. Глобальные env-флаги не переключаются
между конкурентными запросами; состояние pruning не разделяется. Базовый
`text2sql_implementation.py` не изменён. Илья сможет подключать свою модель
через тот же клиент, но перенос полезности фичей потребует отдельной проверки.

## Воспроизведение локального обучения

На текущей машине зависимости и энкодер уже подготовлены. Для нового окружения:

```powershell
.venv\Scripts\python.exe -m ensurepip --upgrade
.venv\Scripts\python.exe -m pip install -r requirements-classifier.txt
.venv\Scripts\python.exe scripts/prepare_classifier_encoder.py --download
```

Повторная подготовка проверяет уже скачанный энкодер. Для точного повторения
можно передать `--revision 1110a243fdf4706b3f48f1d95db1a4f5529b4d41`.

```powershell
.venv\Scripts\python.exe scripts/train_multilabel_classifier.py train --dry-run
.venv\Scripts\python.exe scripts/train_multilabel_classifier.py train --out research_results/multilabel_classifier_deepseek_repeat
.venv\Scripts\python.exe scripts/train_multilabel_classifier.py evaluate --out research_results/multilabel_classifier_deepseek_repeat
```

Готовая папка обучения не перезаписывается. При изменении кода, данных или
энкодера создаётся новый эксперимент; live-launcher проверяет эти хеши до
платных запросов. Существующие отчёты Phase 1 и исходные LLM-прогоны сохранены.

## Ручной прогон DeepSeek

Первый запуск выполнен: **55 вопросов BIRD / 2 БД и 45 Ambrosia / 14 БД**, те же test ID.
Это проверка всего пайплайна, включая новые комбинации. Полные 468 вопросов
смешивали бы train/dev/test в одном headline-результате и не нужны для первой
проверки.

PowerShell на этой машине блокирует прямой запуск `.ps1`. Следующая команда
задаёт политику только для отдельного процесса, не меняя системные настройки.

Проверка без SSH, PostgreSQL и DeepSeek:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_multilabel_deepseek.ps1 --dry-run
```

**Платный запуск — только вручную:**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_multilabel_deepseek.ps1
```

Для начала только BIRD можно добавить `--benchmark bird`; Ambrosia —
`--benchmark ambrosia`. Модель и ключ читаются из `.env.deepseek`, а FEAT-переменные
в нём не определяют маску: её выбирает классификатор. В dry-run `enabled_features=[]`
показывает выключенный глобальный фон; реальные маски выбираются для каждого вопроса.

Результаты пишутся в `research_results/multilabel_deepseek_test_20261029/`:

| Файл внутри benchmark | Назначение |
| --- | --- |
| `dataset.json` | Точные ID и исходные вопросы выбранной части |
| `metadata.json` | Модель, hash классификатора, threshold, split, расход и статус |
| `query_results.json`, `report.json` | Ответы и downstream-оценка |
| `selector_decisions.jsonl` | Scores, выбранные/удалённые фичи, статус и расход по вопросу |
| `raw_responses.jsonl` | Вызовы/ответы с db_id и hash вопроса для сопоставления |
| `comparison.json` | Сравнение с baseline, 35 и 14+32+35 ровно на этих же ID |

Расход по вопросу включает ленивую подготовку схемы/описаний, если она была
выполнена на этом вопросе. Он суммирует usage успешных записанных вызовов;
неизвестные расходы скрытых транспортных попыток не выдаются за измеренные.
Probe учитывается отдельно от вопросного контекста. Статические контроли
исторические, новый ответ DeepSeek получен позже; это явно отмечено в comparison.

Запуск использует существующий SSH supervisor и ограниченные подключения к БД,
сохраняет checkpoint. Три последовательные ошибки провайдера или терминальный
код доступа останавливают эксперимент. Завершённые benchmark пропускаются при
повторном запуске с той же идентичностью.

Live-прогон показал улучшение относительно all-false baseline, но снижение
относительно статического 14+32+35. Подстройка по просмотренному test не заменяет новый test.

Проверки: **94 офлайн-теста**, Ruff, реальное локальное обучение и отдельная
оценка, dry-run Python и PowerShell launcher. Все 100 масок поштучного runtime
совпали с замороженной пакетной оценкой; параметры энкодера остались без градиентов.
Позже пользователь выполнил live-прогон; его результаты сохранены отдельно.
Исходные контрольные результаты, обученная модель и датасеты не изменены.
