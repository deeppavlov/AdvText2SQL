## Ручной запуск

| Настройка | Прямой DeepSeek | OpenRouter |
| --- | --- | --- |
| Env-файл | `.env.deepseek` | `.env.openrouter` |
| LLM_BASE_URL | `https://api.deepseek.com` | `https://openrouter.ai/api/v1` |
| LLM_MODEL_NAME | `deepseek-flash` | `deepseek/deepseek-v4.1-flash-1017` |
| Ключ | Из кабинета DeepSeek | Из кабинета OpenRouter, префикс `sk-or-` |
| Отключение thinking | `thinking.type=disabled` | `reasoning.enabled=false` |
| Снимок расходов | Уменьшение баланса DeepSeek в исходной валюте | Изменение usage ключа OpenRouter в USD |

Согласно [документации DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/),
`deepseek-flash` на 24.10.2026 обслуживает V4.1 Flash 1017. Это обновляемый alias,
а не гарантия закрепления server-side версии; в env и протоколе дополнительно
записан заявленный `LLM_MODEL_VERSION=DeepSeek-V4.1-Flash-1017`.
Ключ и параметры БД перенесены в локальный `.env.deepseek`; файл игнорируется Git.

Скрипт использует именно `LLM_MODEL_NAME`, не подменяет его GPT. Значения FEAT и
DATASET_SIZE в env не влияют на эту серию: runner задаёт их явно.
Общая точка входа принимает `--env-file .env.deepseek`; короткая команда ниже
передаёт этот аргумент автоматически.
Не менять модель, провайдера, код и датасеты посреди серии. Ключ можно заменить
без изменения протокола. Для фиксации конкретного OpenRouter-провайдера есть
`--provider SLUG`; одинаковый аргумент нужен во всех возобновлениях.

Из PowerShell в корне проекта проверить весь план без SSH/API/БД:

```powershell
.\local\run_deepseek_ablation.ps1 --dry-run
```

Начать с baseline, FEAT_1 и FEAT_2 на обоих наборах:

```powershell
.\local\run_deepseek_ablation.ps1 --features 1 2
```

После проверки этих результатов запустить остальную стандартную серию:

```powershell
.\local\run_deepseek_ablation.ps1
```

Завершённые конфигурации пропускаются, незавершённая продолжается с checkpoint.
Новый список `--features` расширяет ту же серию при неизменном протоколе.
В Git Bash эквивалент: `bash local/run_feature_ablation.sh --env-file .env.deepseek`.
SSH-туннель устанавливается и контролируется оболочкой на всё время серии.
Если PowerShell блокирует выполнение `.ps1`, используйте явный запуск:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_deepseek_ablation.ps1 --features 1 2
```

Локальный статус и обновление таблицы результатов без SSH/API/БД:

```powershell
.\local\run_deepseek_ablation.ps1 --status
```

## Контроль и сохранение

`experiment.json` содержит модель, параметры, hashes кода/датасетов, список
конфигураций и их контрольные варианты. Другой протокол в ту же папку не
допускается. Проверенные версии I/O и явная смена плана на одиночные флаги
зарегистрированы в `execution_revisions`: исходный протокол сохраняется,
изменения модели, промптов, датасетов и кода генератора отклоняются.
Системная блокировка исключает два одновременных запуска серии
в один каталог; после завершения или аварии блокировка освобождается.

| Условие | Действие |
| --- | --- |
| Процесс бенчмарка завершился с ошибкой | Серия останавливается; следующие фичи не запускаются |
| API вернул 401/402/403/404 | Немедленная остановка после завершения встроенных API-повторов |
| Три последовательных ошибки API/пустых ответа | Остановка без продолжения через fallback генератора |
| Нет обновлений логов, metadata и checkpoint 15 минут | Остановка текущего дочернего процесса и серии |
| В checkpoint восемь последовательных `error` | Остановка для проверки причины |
| Ctrl+C | Остановка текущего процесса и серии; checkpoint сохраняется |

Порогами управляют `--stall-seconds` и `--error-limit`. Это технический контроль,
а не проверка правильности SQL. Он не гарантирует остановку ровно на заданной
сумме денег; расходы дополнительно проверяются в кабинете выбранного провайдера.

```text
research_results/deepseek_direct_ablation_large_20261024/
├── experiment.json             # Неизменный протокол и расширяемый план
├── suite_status.json           # Состояние последнего ручного запуска серии
├── summary.md / summary.json   # Сравнения с нужным контрольным вариантом
├── monitor_stop.json           # Причина остановки, если она была
├── baseline/
│   ├── bird/                   # 241: metadata, checkpoint, report, лог, raw responses
│   └── ambrosia_227/           # 227: те же артефакты и метрики неоднозначности
├── feat_1/
├── feat_2/
├── feat_3/                     # Только FEAT_3, контроль baseline
└── ...
```

Сводка включает Accuracy, изменение относительно контроля, F1 Ambrosia,
токены всех записанных попыток и приблизительное изменение баланса/расхода ключа.
Баланс DeepSeek может быть в CNY: валюта сохраняется, пересчёт в USD не делается.
Если снимка нет, в таблице стоит «—», а не нулевая стоимость.
Probe-запросы и вызовы подготовки схем записываются в raw responses;
snapshot расхода может запаздывать и учитывать чужие параллельные обращения.
Каждый бенчмарк делает один короткий probe перед подготовкой схем.
Прямой DeepSeek требует нативный `thinking.type=disabled`
([документация](https://api-docs.deepseek.com/guides/thinking_mode/)); вместо
OpenRouter `/key` используется [DeepSeek `/user/balance`](https://api-docs.deepseek.com/api/get-user-balance/).
Настройки OpenRouter не отправляются в прямой API.
Для классификатора нужно хранить также парные правильности ответов; средний
прирост таблицы сам по себе не является разметкой оптимальных фичей.
