| Компактные статистики | 2+7+14+32+35 | 241 | 211 |

Всего **8 запусков, 1 808 обработок вопросов**. Это не число LLM-вызовов:

Ambrosia использует согласованный набор 211: из прежних 227 исключены 16 вопросов
с обнаруженным несоответствием эталонного SQL схеме. Папка `ambrosia_227` сохраняет
историческое имя, фактический знаменатель здесь 211. Исходные датасеты не меняем.

## Протокол и ограничения

Модель DeepSeek, параметры генерации, промпты, evaluator и защита SQL сохранены
из завершённой transportfix-кампании. Источник и код закреплены SHA-256.
Используется `.env.deepseek`; несовпадение модели/версии/endpoint блокирует запуск.
Ответы train/dev не подставляются вместо свежих full-ответов.

Перед генерацией выполняется проверка живых схем с ограниченными повторами
соединения. Первая транспортная ошибка API останавливает текущий вопрос до
сохранения ошибочного checkpoint; сохранённые корректные ответы остаются для
продолжения. Невалидный ответ модели учитывается как ошибка модели по прежним
правилам, без скрытого восстановления ради улучшения метрики.

Full включает уже просмотренные данные. Итоговая таблица описательная, не новый
независимый test и не основание продолжать подбор масок на этих же ответах.
Один full-повтор также не устраняет вариативность модели: вывод об устойчивости
опирается на проведённые train/dev-повторы. Глобальный максимум не доказан.

В замороженном `static_hybrid_conclusion.json` осталось исходное предложение
трёх профилей/шести запусков. Последующее решение пользователя расширяет его
до четырёх/восьми и закреплено отдельным full-манифестом; исходный итог не переписан.

## Ручной запуск

Из корня проекта в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_full_static_hybrid.ps1
```

Скрипт проверяет конфигурацию, поднимает управляемый SSH-туннель и последовательно
выполняет восемь запусков. Та же команда продолжает прерванную серию и пропускает
завершённые бенчмарки. Ориентир по прежним скоростям — **3–4,5 часа** на всю серию
при стабильных API и соединении; это оценка до запуска.

Офлайн-команды без SSH, обращения к БД и API:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_full_static_hybrid.ps1 --dry-run
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_full_static_hybrid.ps1 --status
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_full_static_hybrid.ps1 --report
```

### Что изменилось относительно H

«Исправлено» — H ошибся, кандидат ответил правильно; «ухудшено» — наоборот.

| Кандидат | BIRD: исправлено / ухудшено | Ambrosia: исправлено / ухудшено | Разница среднего к H, п.п. |
| --- | ---: | ---: | ---: |
| 14+32 | 7 / 9 | 7 / 2 | +0,77 |
| 2+7+14+32+35 | 13 / 7 | 2 / 2 | +1,24 |

Compact против 14+32: на BIRD исправлено 18 ответов и ухудшено 10, итог +8;
на Ambrosia исправлено 2 и ухудшено 7, итог −5. Поэтому выигрыш среднего всего
**0,47 п.п.**, а токенов больше на **47,58%**. Эффект статистик на опоре H в этом
проходе сосредоточен на BIRD; равная итоговая Accuracy Ambrosia скрывает разные
ответы, а не доказывает отсутствие влияния.

### Ошибки и исправность

| Профиль | BIRD: ошибки генерации | BIRD: ошибки исполнения, включая SQL `error` | Ambrosia: ошибки генерации / исполнения |
| --- | ---: | ---: | ---: |
| Baseline | 2 | 10 | 0 / 0 |
| H | 3 | 8 | 0 / 0 |
| 14+32 | 3 | 10 | 0 / 0 |
| Compact | 4 | 6 | 0 / 0 |

Все 12 ошибок генерации BIRD — `multiple_statements`: защитный контракт отклонил
несколько SQL-операторов. Это ошибки ответов модели, учтённые в метриках без
дополнительных попыток; они уже входят в число ошибок исполнения, складывать
два столбца нельзя. Среди сырых ответов нет `null`, журналов transport_events
нет, в metadata нет накопленных API-ошибок. На BIRD ложных ответов ambiguous — 0
во всех профилях. На Ambrosia неоднозначность всё ещё распознаётся неполно:
лучший здесь 14+32 обнаружил 30 из 63 неоднозначных вопросов при 9 ложных тревогах.

### Вывод и дальнейший шаг

Компактные статистики дали лучший наблюдаемый full-результат на BIRD и по среднему;
14+32 лучше на Ambrosia и экономнее. H уступает обоим по среднему этого прохода.
Преимущество единственной конфигурации на всех бенчмарках не установлено.

Замороженный выбор по трём dev-повторам остаётся **14+32**. Full-проход добавляет
описательное сравнение с compact, но не заменяет правило выбора новым подбором
на просмотренных данных. Устойчивое превосходство compact над 14+32 или H и
глобальный максимум этим одним проходом не доказаны.

Ограниченный поиск и запланированное full-сравнение можно закрыть. Сохраняем H
как исторический контроль, 14+32 как выбранную опору, compact как альтернативу
для сравнения. Следующий согласованный пункт Roadmap — ограниченный пилот
[оптимизации промптов](15_prompt_optimization_plan.md) на train/dev; затем
пересборка полезности конфигураций и улучшение классификатора. Автоматический
выбор по типу бенчмарка или эталонным ответам не считаем обученным селектором.
