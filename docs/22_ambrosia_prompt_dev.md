07.11.2026. **Все три ручных dev-повтора завершены**, 552/552 уникальных оценок.

промптов с inner-val на фиксированный dev. Поиск повторять не нужно.

Итого **7 логических условий, 4 разных промпта**, 184 уникальных оценки
на повтор, **552 на серию**. Внутри повтора одинаковые условия используют
один сохранённый ответ. Между повторами и из старого search кэш не переносится.
Совпавшие условия не являются дополнительными независимыми наблюдениями.
Порядок четырёх промптов циклически меняется между повторами.

Проверяется именно taxonomy-инструкция; SQL-промпт, модель, retry, схема и
остальной генератор сохраняются. Однозначные вопросы проходят прежний путь
генерации SQL; один вопрос может требовать больше одного обращения к модели.
Accuracy Ambrosia здесь не означает SQL EX: исполнение SQL не является
основной метрикой этого бенчмарка. Ответ `error` не засчитывается как правильное
решение «однозначно».

## Ручной запуск

Из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_ambrosia_prompt_dev.ps1 --max-jobs 3 --transient-resumes 2
```

Та же команда продолжает прерванную серию: завершённые повторы и ответы
пропускаются. Для одного повтора: `--repeat 1 --max-jobs 1`.
Ориентир **40–75 минут** на серию без сбоев; оценка до первого dev-запуска.

Launcher сам поднимает туннель через `local/start_tunnel.sh` и завершает его
при выходе. После проверки frozen identity выполняется проверка живых схем
всех 46 вопросов; при несоответствии/недоступности БД платная генерация не
начинается. Проверка читает только Ambrosia и не подключается к BIRD.

Офлайн, без SSH/БД/API:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_ambrosia_prompt_dev.ps1 --dry-run
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_ambrosia_prompt_dev.ps1 --status
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_ambrosia_prompt_dev.ps1 --report
```

Manifest уже подготовлен. Новый протокол/код требует отдельного output:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_ambrosia_prompt_dev.ps1 --prepare --output research_results/ambrosia_prompt_dev_new
```

Это потолки, не обязательный расход и не долларовый лимит. Учёт отдельный от
старой серии; исходные 60 млн и старые счётчики не сбрасываются/не расширяются.
Подтверждённые transient 429/500/502/503/504 могут получить до двух внешних
возобновлений по явному флагу выше; неизвестное списание резервируется
консервативно с журналом до/после. Billing/auth/timeout не возобновляются
автоматически; provider/DB outage не записывается как модельная ошибка.

```text
research_results/ambrosia_prompt_dev_20261107/
├── experiment.json             # Вопросы, кандидаты, source SHA, лимиты, код
├── report.md / report.json     # Парные сравнения, ошибки, F1, mean/SD

```

Реализация: `scripts/ambrosia_prompt_dev.py`, launchers `local/run_ambrosia_prompt_dev.ps1/.sh`.
Переиспользуются hash-pinned runtime, запись fsync и supervisor из предыдущих
серий; их исходные файлы не изменены. Исторические search selections не
перезаписываются, original all-24 confirmation не вызывается.

Проверка: **8 новых офлайн-тестов** — весь shortlist и порядок, точная маска
при реальном tool construction и query, исходный taxonomy round-trip,
неизменность SQL-шаблона, запрет dev-примеров/teacher, cache/resume только в
своём повторе, запрет чужих checkpoint, preflight Ambrosia, строгий учёт ошибок
и выбор только после трёх повторов. API/БД подменены, новые соединения в
runtime-тестах заблокированы. Полный Windows launcher проверен с `--dry-run`.

Dev уже просматривался на прежних этапах: выводы ретроспективные. После
результатов фиксируем промпт Ambrosia, затем готовим сравнение с исходным
на полном согласованном наборе **211**, отдельно от BIRD **241** с compact.
Проценты dev/inner/full напрямую между собой не ранжируем. Перед следующей
итерацией классификатора пересобираем совместимые train utility-метки.
