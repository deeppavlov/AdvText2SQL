## Зафиксированный протокол

| Параметр | Значение |
| --- | --- |
| Набор | **211 вопросов**, те же ID/формулировки, что в статическом full 03–04.11 |
| Состав | 63 неоднозначных, 148 однозначных; **51 БД** |
| Фичи | Только **14+32**, остальные FEAT false независимо от env |
| SQL-промпт | Исходный SQL_PROMPT_TEMPLATE и SQL_PROMPT_BASIC |
| Taxonomy-промпт | Исходный, выбранный завершённым Ambrosia dev |
| Промпт BIRD MIPRO seed 43 | **Не переносится** на Ambrosia |
| Модель | Прежний DeepSeek Flash из `.env.deepseek`, identity/options закреплены |
| Объём | Один свежий full-контроль, **211 оценок**, не обязательно 211 API-вызовов |
| Teacher / поиск / новые demos | Нет, teacher_calls=0 |
| Метрики | Строгая Accuracy решения о неоднозначности, F1, precision/recall, TP/FP/FN/TN, generation errors |
| Исторический ориентир | 169/211 — 80,09%, F1 58,82%; отдельный прежний проход |

Набор уже согласован: из прежних доступных 227 исключены 16 вопросов с
несоответствием SQL/схемы. Три пустые БД были исключены ещё до этого. Исходные
датасеты не меняем, новые вопросы вместо исключённых не добавляем.

Все ответы получаем заново в новом output. Search, dev и предыдущий full не
подставляются. Исторический отчёт служит только числовым ориентиром, а не
источником новых ответов. Сравнение свежего и старого контроля не является
экспериментом «оптимизированный против исходного» — промпты сохранены.

Accuracy Ambrosia не означает SQL EX: важно верно отличить неоднозначный
вопрос от однозначного. Для однозначных вопросов генератор проходит прежний
путь SQL; `error` всегда считается ошибкой, не правильным «однозначно».
Исполнение эталонного SQL не используется для этой метрики; текущие эталоны
не передаются в LLM. До платных вызовов проверяются живые схемы всех 211
вопросов. Подключений к BIRD и переноса его новой инструкции нет.

## Ручной запуск

Из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_ambrosia_prompt_full.ps1 --transient-resumes 2
```

Ориентир **20–40 минут** без длительных сбоев, по скорости завершённого dev.
Launcher поднимает SSH через `local/start_tunnel.sh` и закрывает туннель при
выходе. Та же команда продолжает прерванный запуск, пропуская сохранённые
завершённые ответы. Незавершённый вопрос может потребовать повторного обращения;
прежний учтённый расход при этом не удаляется.

Офлайн, без SSH/БД/API:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_ambrosia_prompt_full.ps1 --dry-run
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_ambrosia_prompt_full.ps1 --status
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_ambrosia_prompt_full.ps1 --report
```

Manifest уже подготовлен. Новый код/протокол требует отдельного output:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_ambrosia_prompt_full.ps1 --prepare --output research_results/ambrosia_prompt_full_new
```

Потолок не означает обязательный расход или долларовый лимит. Новые ledger
отдельны от прежних серий, старые счётчики не сбрасываются. Подтверждённые
transient task 429/500/502/503/504 допускают максимум два внешних возобновления
с консервативным журналируемым учётом неизвестного расхода. Billing/auth/timeout
автоматически не возобновляются; недоступная БД/провайдер не даёт отрицательную
модельную метку.

```text
research_results/ambrosia_prompt_full_20261107/
├── experiment.json             # Full, исходный dev отдельно, шаблоны, код/источники SHA
├── report.md / report.json     # Метрики и расход свежего full, отдельный исторический ориентир
├── budget.json                 # При запуске, авторитетный суммарный учёт
├── conclusion.json             # После 211 ответов; selection_on_full=false
└── jobs/ambrosia_full__control/
    ├── evaluations.json        # Свежие ответы, score и usage
    ├── candidates.json
    └── confirm/                # Внутреннее имя runtime; scope обязательно FULL
        ├── metadata.json       # evaluation_scope=full_retrospective
        ├── budget.json
        └── comparison.log      # Raw/журналы пишутся локально и исключены из Git
```

Реализация: `scripts/ambrosia_prompt_full.py`, `local/run_ambrosia_prompt_full.ps1/.sh`.
Переиспользуем hash-pinned schema preflight, генератор, бюджеты, durable IO и
supervisor. Оба SQL-шаблона явно фиксируются на исходных значениях при запросе;
taxonomy разрешён только исходный, с пустым списком demonstrations. Служебная
фаза `confirm` не делает этот набор dev: в manifest он записан в `full`, а
scope metadata запрещает подмену dev-checkpoint.

Проверки: **8 новых офлайн-тестов** — точные исходные шаблоны/маска, запрет
изменённой инструкции и teacher, реальное построение tools на full, разделение
full/dev, новый query и возобновление из своего checkpoint, Ambrosia-only
schema preflight без исполнения reference SQL, остановка до API при сбое БД,
строгая обработка `error`, защита scope и subprocess reentry. В runtime-тестах
API/БД подменены, сетевые соединения заблокированы. Windows launcher проверен
целиком с `--dry-run`; при подготовке нет ни task ledger, ни jobs.

Один полный проход на ранее просмотренных данных — ретроспективный контроль,
не независимый тест. После завершения фиксируем рядом свежие BIRD и Ambrosia
метрики с разными профилями; только затем готовим совместимые train utility-метки
и следующий эксперимент классификатора. Полные/dev-ошибки не добавляем в train.
