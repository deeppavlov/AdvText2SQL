# BIRD: полный парный контроль зафиксированного SQL-промпта

07.11.2026. **Полный ручной прогон завершён: 482/482 оценки.**
После [compact-dev](21_bird_compact_prompt_transfer.md) фиксируем один
конкретный SQL-промпт и сравниваем с исходным на полном согласованном BIRD.
[Ambrosia dev](22_ambrosia_prompt_dev.md) сохранил исходный taxonomy-промпт,
поэтому второй идентичный «оптимизированный» Ambrosia-прогон сюда не включён.

## Результаты полного сравнения

Запуск прошёл с 21:52 до **22:55 МСК**, около **63 минут**, код выхода 0.
Проверены 482 точных ключа ответов (оба промпта × все 241 ID), маска, source
SHA, версия кода и зафиксированный до full кандидат. Pending пусты в обоих
ledger, teacher=0; неизвестного расхода нет.

Прирост — **6 правильных ответов** в паре. Это не случай «исправил только
формат»: среди 17 исправленных вопросов лишь один имел у исходного ошибку
формата/SQL. Остальные пять исходных ответов с такими ошибками в новом

output contract; два SQL errors — SQLSTATE 22007 и 42703. Они не являются

## Что именно фиксируем

| Параметр | Значение |
| --- | --- |
| Данные | Те же **241 BIRD-вопрос**, что в полном статическом сравнении 03–04.11 |
| Фичи обоих условий | Только **2+7+14+32+35**, остальные FEAT false |
| Контроль | Исходная SQL-инструкция compact; не all-false baseline |
| Новый вариант | Кандидат MIPRO few-mode, optimizer seed **43** (`sql__mipro_few__r2`) |
| Демонстрации нового варианта | **0** — фактически новая инструкция без few-shot примеров |
| Candidate SHA | `fb9b0607f7f656a62c4e58482c6f638268ca4fab9fbabe097dcfb9953b523ffb` |
| Модель | Та же DeepSeek Flash из `.env.deepseek`; версия/endpoint/options закреплены |
| Teacher / оптимизация | Запрещены, teacher_calls=0 |
| Повторы | Один свежий парный full-проход двух зафиксированных условий |
| Объём | **241 × 2 = 482 оценки**, не обязательно 482 API-вызова |
| Порядок | Два промпта подряд на одном вопросе; первый/второй чередуются по вопросам |
| Метрики | SQL EX, исправлено/ухудшено относительно контроля, generation/SQL errors, ложная неоднозначность, токены |

Средний dev EX выигравшего режима MIPRO few-shot был 45,45% против исходных
38,79%. Это среднее **трёх разных выбранных промптов**, не оценка одного
зафиксированного текста. Для полного контроля теперь нужно выбрать конкретный
текст до первого full-вызова:

| Исходный поисковый seed | Компактный dev EX | Демонстрации |
| --- | ---: | --- |
| 42 | 25/55 — 45,45% | 631, 699 |
| **43** | **26/55 — 47,27%** | **Нет** |
| 44 | 24/55 — 43,64% | 631, 726 |

Правило нового решения закреплено сейчас: сначала сохраняем режим, выбранный
по среднему трёх source-повторов, затем берём его конкретный кандидат с лучшим
dev EX; при равенстве — меньше примеров, короче инструкция, ранний source repeat.
Это решение до full, оно не было правилом исходного dev-эксперимента. Кандидат
seed 43 — лучший **наблюдаемый** на dev; одна-две разницы в ответах не доказывают
его устойчивого превосходства над другими seed.

Название MIPRO few-mode означает, что оптимизатор мог выбрать 0–2 примера;
в данном случае он выбрал ноль. Поэтому отчёт и условие запуска называются
`selected_sql`, а не «новый few-shot»: выигрыш нельзя приписывать демонстрациям.
При сравнении меняется только SQL-инструкция, исходный taxonomy и фичи одинаковы.

## Ручной запуск

Из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_bird_prompt_full.ps1 --transient-resumes 2
```

Ориентир **45–90 минут** без длительных сбоев, оценка до запуска. Та же команда
продолжает прерванную серию и пропускает только завершённые ответы в новом output.
Не подставляются ответы прежнего full, compact-dev или search.

Перед платными вызовами проверяются source-файлы, код и параметры модели,
живые схемы и исполнение **всех 241 эталонных SQL в read-only транзакциях**.
Эталоны используются evaluator и не передаются генератору. БД/провайдер,
которые недоступны, останавливают запуск без отрицательной модельной метки.

Launcher сам управляет SSH-туннелем через `local/start_tunnel.sh`.
Офлайн-команды без SSH/БД/API:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_bird_prompt_full.ps1 --dry-run
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_bird_prompt_full.ps1 --status
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_bird_prompt_full.ps1 --report
```

Manifest уже подготовлен. После изменения кода/протокола нужен новый output:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_bird_prompt_full.ps1 --prepare --output research_results/bird_prompt_full_new
```

## Учёт и ограничения

| Жёсткий потолок | Локальный job | Вся новая серия |
| --- | ---: | ---: |
| Оценки | 550 | 550 |
| Task-вызовы | 2 000 | 2 000 |
| Teacher-вызовы | 0 | 0 |
| Токены | 8 000 000 | 9 000 000 |
| Активное время | 4 часа | 4 часа |

Потолки не являются плановым расходом или долларовым лимитом. Прежние
счётчики не обнуляются; новая серия имеет свой ledger. До двух внешних
возобновлений разрешены только подтверждённым transient task-ошибкам
429/500/502/503/504, с консервативным журналируемым учётом неизвестного расхода.
Billing/auth/timeout не запускаются повторно автоматически.

```text
research_results/bird_prompt_full_20261107/
├── experiment.json             # Отдельный full, неизменные исходные dev/fit, source SHA, код
├── frozen_candidate.json       # Конкретный текст, demos=[], правило выбора и source identity
├── report.md / report.json     # Парные EX/ошибки/расход обоих условий
├── budget.json                 # При ручном запуске: общий авторитетный расход
├── conclusion.json             # После 482 оценок, selection_on_full=false
└── jobs/bird_full__paired/
    ├── evaluations.json        # Новые ответы обоих промптов, отдельные ключи
    ├── candidates.json
    └── confirm/                # Внутреннее имя унаследованного runtime, фактически FULL
        ├── metadata.json       # Обязательный evaluation_scope=full_retrospective
        ├── budget.json
        └── comparison.log      # Локальные журналы/raw не добавляются в Git
```

Реализация: `scripts/bird_prompt_full.py`, `local/run_bird_prompt_full.ps1/.sh`.
Служебная фаза `confirm` переиспользует проверенные бюджеты/transport. В manifest
набор явно записан в **full**, исходный dev сохранён отдельно; proxy на full
используется только внутри runtime. Проверка scope запрещает чужие dev-checkpoint.
Учёт токенов по вопросам в arm не включает build/unknown overhead; итог берём
из общего ledger, не суммируем повторно локальный и глобальный бюджеты.

Пройдены **9 новых офлайн-тестов**: конкретный dev-выбор без подмены нулевых
демонстраций, парный порядок, реальное tool construction на full, точные FEAT,
отсутствие текущего gold в промпте, self-contained cache/resume, запрет teacher,
реальный read-only preflight всех fixture-эталонов, остановка до API при сбое
preflight, запрет чужого scope, отчёт без нового выбора по full и worker reentry.
API/БД подменены, новые подключения в runtime-тестах заблокированы. Windows
launcher проверен целиком с `--dry-run`.

Полный набор включает уже просмотренные train/inner/dev. Это **ретроспективный
контроль**, а не независимый тест обобщения. Один свежий проход оценивает пару
на этом наборе, но не измеряет SD по повторным full-запускам. Результат не
возвращается teacher и не используется для дальнейшего поиска промпта.
`conclusion.json` описывает исходы, а не автоматически внедряет победителя.
После разбора — фиксация рабочей версии и обновление только train utility-меток
для следующего обучения классификатора с сохранением групповых splits.
