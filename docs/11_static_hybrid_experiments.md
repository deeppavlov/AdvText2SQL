# Поэтапные эксперименты статического гибрида

29.10.2026. Реализация [плана поиска](10_static_hybrid_search.md) подготовлена.
Пользователь завершил первый этап `core` на train: четыре benchmark-запуска,
534 обработки вопросов, затем контрольный повтор H: ещё два запуска и 267 вопросов.
Этап additions также завершён: 18 запусков и 2 403 обработки вопросов. Dev/full
для новых масок не запускались. [Итоги additions и исправления качества данных](12_results_and_data_quality.md)
уточняют результаты ниже: найдены невалидные ответы и 16 несоответствий схем Ambrosia.
Для следующих запусков подготовлен отдельный v3; старый v2 сохранён.

## Итоги ядра на train, 29.10.2026

Исторические контроли пересчитаны на тех же 131/136 вопросах. Шесть прежних масок
и две новые замыкают все восемь подмножеств {14,32,35}.

| Маска | Источник | BIRD, 131 | Ambrosia strict, 136 | F1 Ambrosia | Средняя Accuracy |
| --- | --- | ---: | ---: | ---: | ---: |
| Baseline | Исторический | 67 = 51,15% | 93 = 68,38% | 0,00% | 59,76% |
| 14 | Исторический | 71 = 54,20% | 94 = 69,12% | 12,50% | 61,66% |
| 32 | Исторический | 69 = 52,67% | 103 = 75,74% | 49,23% | 64,20% |
| 35 | Исторический | 71 = 54,20% | 94 = 69,12% | 8,70% | 61,66% |
| 14+35 | Исторический | **74 = 56,49%** | 92 = 67,65% | 4,35% | 62,07% |
| 14+32 | Новый | 72 = 54,96% | 105 = 77,21% | 52,31% | 66,08% |
| 32+35 | Новый | 72 = 54,96% | 103 = 75,74% | 49,23% | 65,35% |
| **14+32+35 (H)** | Исторический | **74 = 56,49%** | **107 = 78,68%** | **55,38%** | **67,58%** |

Снятие 35 относительно H даёт −2 ответа BIRD и −2 Ambrosia; снятие 14 — −2 BIRD
и −4 Ambrosia. Парные изменения показывают, что наборы ошибаются по-разному:

| Новая маска относительно H | BIRD: исправлено / испорчено | Ambrosia: исправлено / испорчено |
| --- | ---: | ---: |
| 14+32 | 4 / 6 | 2 / 4 |
| 32+35 | 5 / 7 | 1 / 5 |

**H лидирует по наблюдаемой средней Accuracy среди восьми масок ядра. На BIRD у
него равенство с 14+35.** Это результат на train, а не доказательство глобального
максимума или статистически устойчивого превосходства: разницы небольшие,
контроли получены раньше и повторов пока нет.

### Вариативность детектора: существенная оговорка

У 32+35 все **86/86** записанных запросов к taxonomy-детектору Ambrosia дословно
совпадают с запросами прежнего H для соответствующих вопросов. Тем не менее,
в шести случаях поменялся вердикт:

| question_id | Прежний H: ambiguous | Новый 32+35: ambiguous |
| --- | --- | --- |
| 19 | false | true |
| 32 | true | false |
| 55 | false | true |
| 59 | false | true |
| 60 | true | false |
| 279 | true | false |

FEAT_14 меняет SQL-промпт, а не taxonomy-промпт. Поэтому −4 ответа Ambrosia здесь
нельзя объяснить прямой пользой 14 для детекции. Зафиксирована вариативность ответов
на одинаковые сообщения; причина на стороне модели/инференса по локальным файлам
не установлена. У 14+32 представление схемы другое, совпадений taxonomy-сообщений
с H нет. Это различие нужно учитывать отдельно.

## Контрольный повтор H: вывод уточнён

Повтор завершился 29.10.2026 в 13:16 МСК; все 267 вопросов обработаны, ошибок
генерации нет. Три ошибки исполнения BIRD учтены как неверные ответы.

| Конфигурация | BIRD, 131 | Ambrosia, 136 | F1 Ambrosia | Средняя Accuracy |
| --- | ---: | ---: | ---: | ---: |
| H, исторический контроль | 74 = 56,49% | 107 = 78,68% | 55,38% | 67,58% |
| H, свежий повтор | 72 = 54,96% | 102 = 75,00% | 48,48% | 64,98% |
| 14+32, свежий | 72 = 54,96% | **105 = 77,21%** | **52,31%** | **66,08%** |
| 32+35, свежий | 72 = 54,96% | 103 = 75,74% | 49,23% | 65,35% |

По сравнению с историческим H сам повтор исправил 1 и испортил 3 ответа BIRD,
исправил 1 и испортил 6 ответов Ambrosia. Наблюдаемый разброс одного и того же H
составил −1,53 п.п. BIRD и −3,68 п.п. Ambrosia — он сопоставим с предыдущими
различиями между масками. Это не оценка дисперсии по двум независимым повторностям:
даты/серверные условия и состав всего запуска различаются.

Все 86 taxonomy-сообщений повтора совпали с историческим H; вердикт изменился у
семи вопросов (19, 32, 55, 59, 60, 269, 279). По сравнению со свежим 32+35 те же
86 сообщений совпали, а вердикт различался только у вопроса 269. Причину различий
инференса по локальным артефактам установить нельзя. Значит, прямого подтверждения
пользы FEAT_14 для Ambrosia здесь нет.

| Маска относительно свежего H | BIRD: исправлено / испорчено | Ambrosia: исправлено / испорчено |
| --- | ---: | ---: |
| 14+32 | 4 / 4 | 4 / 1 |
| 32+35 | 7 / 7 | 1 / 0 |

**Предыдущее лидерство H по исторической таблице не подтверждено свежим контролем.**
Среди трёх свежих запусков 14+32 сейчас имеет лучший общий скор, но одного прохода
на маску недостаточно, чтобы объявить устойчивый максимум или окончательно удалить 35.
На BIRD все три свежих маски равны по Accuracy и различаются конкретными ошибками.

Повтор использовал 832 627 записанных токенов и 462 LLM-вызова, около 32 минут.
Сумма снимков баланса $0,31 остаётся расходом аккаунта за интервал, не точным счётом
за этот эксперимент. Результаты предыдущих запусков не переписывались.

Штатная summary-колонка `Delta H` сохраняет **исторический** контроль по замороженному
протоколу. Для текущего сравнения добавлен отдельный
[отчёт со свежим контролем](../research_results/deepseek_combinations_large_20261026/search_v2_20261029/current_control_comparison_train.md).
В JSON рядом — парные изменения ID, сравнение сообщений детектора и source hashes.
Его можно обновлять офлайн после следующих этапов:

Следующий шаг — запланированный `additions`: H плюс одна из 2/15/16/21/23/25/28/29/30.
Это измерение условной пользы механизмов поверх заранее заданной точки H, а не
утверждение её оптимальности. Сравниваем кандидатов со свежим H и 14+32; последнюю

## Выборки и сравнения

| Scope | BIRD | Ambrosia | Назначение |
| --- | ---: | ---: | --- |
| `train`, по умолчанию | 131 | 136 | Поиск комбинаций на прежнем групповом split |
| `dev` | 55 | 46 | Подтверждение выбранных финалистов |
| `full` | 241 | 227 | Исследовательское сравнение с прежними полными таблицами |

Прежний test не включён в train/dev. В full он входит; full уже использовался
для исследовательского выбора и не является новым независимым тестом.
Исторические baseline, 14, 32, 35, 14+35 и H=14+32+35 пересчитываются офлайн
на **тех же ID**, что новые ответы каждого scope. Контрольные API-прогоны не
повторяются скрытно. В summary.json также сохраняются изменения к непосредственному
родителю и число исправленных/испорченных ответов.

Прямой DeepSeek, `.env.deepseek`, модель/объявленная версия, промпты и оценщики
сверяются с прежними экспериментами. Модельный alias провайдера не гарантирует
неизменность серверных весов между днями. Для проверки устойчивости доступен
отдельный повтор H. Температура 0 не заменяет повторных измерений.

## Первый запуск из PowerShell в корне проекта

Проверка, не открывающая SSH и не вызывающая API:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_static_hybrid_search.ps1 --dry-run
```

Запуск **только первых двух масок** на обоих train-бенчмарках:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_static_hybrid_search.ps1 --stage core
```

| Очередь | Маска | BIRD | Ambrosia |
| --- | --- | ---: | ---: |
| 1 | 14+32 | 131 | 136 |
| 2 | 32+35 | 131 | 136 |

Всего четыре benchmark-запуска, 534 обработки вопросов. Число LLM-вызовов другое:
checker и SQL обычно отдельные вызовы, часть вопросов заканчивается раньше.
Первые шесть подмножеств ядра уже измерены исторически; новые два замыкают восемь
масок ядра на соответствующей выборке. Это не полный перебор всех фичей проекта.

Повтор той же команды продолжает checkpoint и пропускает завершённые benchmark-запуски.
Статус без SSH/API:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_static_hybrid_search.ps1 --status
```

При необходимости проверить первые две маски сразу на прежнем полном наборе:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_static_hybrid_search.ps1 --stage core --scope full
```

Это четыре запуска, 936 обработок вопросов. Их файлы не смешиваются с train.
Переход к full не происходит автоматически.

## Последующие этапы — после анализа предыдущего

| `--stage` | Содержание | Новых масок | Что требуется перед train-запуском |
| --- | --- | ---: | --- |
| `core` | 14+32; 32+35 | 2 | Исторические контроли уже готовы |
| `additions` | H + одна из 2/15/16/21/23/25/28/29/30 | 9 | Исторический H |
| `statistics` | H+2+7, затем +3, затем +4 | 3 | Завершён H+2 |
| `repair` | H+15+16, затем +17, +27, +20 | 4 | Завершены H+15 и H+16 |
| `interactions` | H+15+16+28; H+29+30 | 2 | Соответствующие родительские прогоны |

Например, следующий этап после разбора ядра:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_static_hybrid_search.ps1 --stage additions
```

Можно выбирать несколько конкретных масок вместо целого этапа. Все названия и маски
находятся в experiment.json. Например, ограниченная проверка обработки SQL:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_static_hybrid_search.ps1 --cases hybrid_plus_15 hybrid_plus_16
```

Отдельный повтор H, не входящий в автоматическую очередь этапов:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_static_hybrid_search.ps1 --cases hybrid_control_repeat
```

Финалиста можно подтвердить на dev без повторения всех его промежуточных родителей.
Пример ниже — форма команды, а не утверждение, что данная маска уже выиграла:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_static_hybrid_search.ps1 --scope dev --cases core_without_rules
```

`--benchmark bird` или `--benchmark ambrosia` ограничивает запуск одним набором.
Общий скор нового кандидата появляется только после завершения обоих бенчмарков
в одном scope. `--stage all` явно запускает все 20 гипотез; по умолчанию он не выбран.
Все этапы используют явные маски: они не накапливают флаги предыдущего запуска и
не наследуют FEAT_N из env. Число фичей в меню достигает восьми, а не ограничено тремя.

После результатов этих гипотез следующий раунд добавлений/удалений/замен строится
вокруг нескольких train-лидеров. Автоматического запуска такого адаптивного раунда
сейчас нет: его состав зависит от ещё не полученных ответов и фиксируется отдельно.

## Надёжность и учёт

- Перед SSH выполняется локальная проверка модели, кода, данных и нужных train-контролей.
- Один SSH watchdog обслуживает выбранный этап. Сбой провайдера, 8 последовательных
  ошибок генерации или отсутствие активности 900 секунд останавливают очередь.
- Изменение модели, протокола, кода или cohort не допускает смешивания checkpoint;
  для новой версии требуется новая подпапка через `--output`.
- Checkpoint записывается атомарно после каждого вопроса. После сбоя уже сохранённые
  вопросы не отправляются повторно. Прерванный незавершённый вопрос может потребовать
  повторного LLM-вызова; предыдущий raw response сохраняется, если запись успела завершиться.
- Если все ответы готовы, а оценивание прервалось, повтор выполняет только оценку,
  без probe/build/генерации. Ошибки эталона/неопределённого источника не превращаются
  молча в неудачу модели и блокируют итоговое сравнение до разбора.
- `raw_responses.jsonl` сохраняет фазу probe/build/question, ID вопроса и usage каждого
  записанного ответа. `question_usage.jsonl` — отдельно расходы вопроса; build считается
  отдельно. Транспортные повторы без записанного ответа могут не входить в суммы.
- В таблице — Accuracy обоих наборов, F1/recall/FP Ambrosia, ошибки, токены/вызовы,
  приблизительные снимки баланса с сохранением валют. Исторические расходы отдельных
  train/dev-вопросов неизвестны; экономия относительно них не придумывается.

Результат реализации проверен офлайн: маски и зависимости, разделение scope,
строгая оценка, возобновление, пропуск завершённых запусков и остановка провайдера.
Платные вызовы в рамках подготовки не выполнялись.
