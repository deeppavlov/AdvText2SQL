# BIRD: перенос SQL-промптов на compact

07.11.2026. **Серия завершена: три повтора, 880 уникальных оценок.**
Основная опора BIRD по решению пользователя — **2+7+14+32+35**. На текущем шаге
проверяем, улучшают ли её SQL-промпты, найденные в предыдущей серии на 14+32.
Нового обучения оптимизаторов/teacher здесь нет. Ambrosia не запускается.

## Фиксированный протокол

| Параметр | Значение |
| --- | --- |
| Модель / подключение | Прежний DeepSeek Flash, прямой API, `.env.deepseek`, thinking disabled |
| Фичи | Только **2, 7, 14, 32, 35**; явно при build и query |
| Вопросы | **55 frozen BIRD dev**, те же ID/БД, что в исходном протоколе |
| Повторы | **3**; кандидаты соответствующих optimizer seeds 42/43/44 |
| Контроль | Исходный промпт на compact; это не all-false baseline |
| Варианты каждого повтора | Исходный; фиксированный few-shot; GEPA; MIPRO zero-shot; TextGrad; MIPRO few-shot |
| Откуда кандидаты | Все 12 завершённых SQL-поисков; никакого выбора удачного seed по dev |
| Демонстрации | Только fit-примеры исходного SQL-поиска, не dev/test |
| Критерий | PostgreSQL EX и парные исправления/ухудшения к исходному compact |
| Выбор после dev | Только после завершения всех трёх повторов: средний EX; при ничьей исходный, затем заранее заданный порядок arms |
| Изоляция | Новый manifest/output и отдельные бюджеты, старые результаты не меняются |

Переносится только SQL-инструкция/fit-демонстрации. Taxonomy-промпт в FEAT_32,
генератор, retry, evidence, SQL output guard, read-only evaluator и пауза между
вопросами унаследованы из исходного стенда. Имеющийся all-false baseline остаётся
историческим контролем; новая таблица измеряет улучшение статического compact.

| Повтор | Уникальные варианты промпта | Вопросы на вариант | Уникальных оценок |
| --- | ---: | ---: | ---: |
| 1 | 4 | 55 | 220 |
| 2 | 6 | 55 | 330 |
| 3 | 6 | 55 | 330 |
| Всего | — | Те же 55 | **880** |

В первом повторе GEPA и MIPRO zero-shot выбрали seed, поэтому повторно
вызывать его для тех же вопросов не нужно. Совпадения кешируются только
внутри одного повтора. Между повторами ответы не разделяются. Старые ответы
14+32 не используются как ответы compact; чужая metadata/маска блокирует resume.
Одна оценка вопроса может включать несколько LLM-вызовов.

## Лимиты и остановки

| Лимит | Один повтор | Вся новая серия |
| --- | ---: | ---: |
| Оценки | 400 | 1200 |
| Task calls, включая build | 1500 | 4500 |
| Teacher calls | **0** | **0** |
| Токены | 3 млн | **6 млн** |
| Активное время | 2 часа | 6 часов |

Это верхние ограничения, не прогноз расхода. Новая серия имеет собственный
бюджет; исходный лимит сравнения оптимизаторов не сбрасывается и не расширяется.
Перед первым оплачиваемым вызовом выполняются schema preflight и исполнение
всех 55 эталонов read-only. Эталон текущего dev-вопроса не попадает в промпт.

HTTP 429/500/502/503/504 без checkpoint: один matching task-резерв учитывается
консервативно, исходные бюджеты и SHA результатов сохраняются в recovery-журнале.
Измеренные input/output и число вызовов не обнуляются; неизвестный расход
отделён от измеренного. Незавершённая запись пары бюджетов может быть завершена
по durable-журналу. Неверный SQL остаётся ошибкой модели; недоступность БД,
оплата/ключ, неизвестный исход или timeout останавливают серию для проверки.

`--transient-resumes 2` разрешает максимум два внешних продолжения с паузами
60/120 секунд после подтверждённых transient task-сбоев. Нет бесконечного retry;
исходно разрешённые повторы не расширяются при перезапуске. Без флага повтор
платного запуска отключён. Все записи JSON/JSONL синхронизируются через fsync.

## Ручной запуск

### Итоги завершённой серии, 07.11.2026

Следующий [BIRD full-протокол](23_bird_prompt_full.md) подготовлен отдельно:
конкретный MIPRO seed 43, dev 26/55, **demos=[]**, против исходного compact
на одинаковых 241 вопросе. Выбранный few-mode кандидат фактически zero-shot;
средний результат режима 45,45% не является оценкой одного этого текста.

Все три повтора завершены: 220 + 330 + 330 = **880 уникальных оценок**.
Последний завершён в 18:57 МСК; процесс вернул код 0. Учтено **9 731 375
токенов**, незакрытых резервов и неизвестного расхода нет. Повторный запуск
закономерно пропускает всю завершённую очередь.

| Промпт | Средний EX, 55 dev-вопросов × 3 повтора | SD, п.п. | Прирост к исходному compact, п.п. |
| --- | ---: | ---: | ---: |
| Исходный | 38,79% | 1,05 | — |
| Фиксированный few-shot | 42,42% | 4,58 | +3,64 |
| GEPA zero-shot | 40,00% | 3,15 | +1,21 |
| MIPRO zero-shot | 43,03% | 5,55 | +4,24 |
| TextGrad zero-shot | 41,21% | 3,78 | +2,42 |
| MIPRO few-shot | **45,45%** | 1,82 | **+6,67** |

MIPRO few-shot дал положительную парную разницу во всех трёх повторах:
+7,27 / +7,27 / +5,45 п.п. Это лучший средний результат среди проверенных
перенесённых промптов; оптимизатор здесь заново не запускался. Выбор arm
не означает автоматическое внедрение и не задаёт единственный лучший seed:
кандидаты в трёх повторах разные, включая разные инструкции и демонстрации.

Нельзя сравнивать эти 45,45% напрямую с прежними 55,88% MIPRO few-shot при
14+32: последние измерены на **68 inner-val**, использованных для отбора
промптов, а здесь — **55 других dev-вопросов**. Dev-серии 14+32 на этих 55
пока нет. В прежнем одинаковом полном BIRD (241 вопрос, исходные промпты)
compact дал 124/241 (51,45%), а 14+32 — 116/241 (48,13%): compact был выше
на 8 ответов. Следовательно, нынешний результат не доказывает проигрыш
compact набору 14+32.

Следующая согласованная очередь — два оставшихся поиска MIPRO zero-shot
для Ambrosia при **14+32** (повторы 2 и 3, по 60 fit/60 inner-val):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_prompt_comparison_resume.ps1 --phase search --slot ambiguity --method mipro_zero --max-jobs 2 --transient-resumes 2
```

Первый повтор этого метода уже завершён и пропускается. Ориентир двух
поисков — **1–2 часа** по первому повтору (около 38 минут). После них нужно
подготовить отдельную Ambrosia dev-проверку на 46 вопросах: исходный промпт
и заранее зафиксированные кандидаты. Исходная all-method confirm-команда
всё ещё требует все 24 поиска; сокращённая очередь её условие не отменяет.

### Исходный запуск с первоначальными лимитами

Все три повтора; совпадающие/завершённые результаты пропускаются при продолжении:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_bird_compact_transfer.ps1 --max-jobs 3 --transient-resumes 2
```

Ориентир **1,5–3 часа** на серию без длительных сбоев API; это прогноз по
предыдущим BIRD-запускам, первый compact-dev ещё не измерен.

Можно сначала запустить только первый повтор, 220 оценок:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_bird_compact_transfer.ps1 --repeat 1 --max-jobs 1 --transient-resumes 2
```

Офлайн, без SSH/БД/API:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_bird_compact_transfer.ps1 --dry-run
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_bird_compact_transfer.ps1 --status
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_bird_compact_transfer.ps1 --report
```

Manifest уже подготовлен. Для нового output после явного изменения протокола:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File local/run_bird_compact_transfer.ps1 --prepare --output research_results/bird_compact_prompt_transfer_new
```

Фичи из env не определяют эту серию: маска закреплена в manifest и применяется
скриптом. Ключ остаётся в `.env.deepseek`. Платный launcher сам поднимает SSH
через `local/start_tunnel.sh`; offline-флаги не запускают туннель.

## Артефакты и проверки

```text
research_results/bird_compact_prompt_transfer_20261107/
├── experiment.json              # Кандидаты/демо-ID, 55 вопросов, маска, лимиты, source SHA
├── report.md / report.json      # EX каждого arm/repeat, парные исходы, среднее/SD, расход
├── budget.json                 # Появится при ручном запуске, полный расход build+questions
├── selection.json              # Только после всех трёх полных повторов; deployment=false

│   ├── evaluations.json         # Новые ответы compact, usage и SQL-диагностика
│   ├── candidates.json          # Фактически использованные инструкции/демо-ID
│   └── confirm/                # Metadata, budget, локальные raw/logs
├── recoveries/                 # Журналы до/после неизвестного расхода, при необходимости
└── resumption_events.jsonl     # Локальный журнал внешних продолжений
```

Реализация: `scripts/bird_compact_transfer.py`, PowerShell/Bash launchers в
`local/`. **14 офлайн-тестов прошли**: provenance выбора, точные фичи при реальном
tool preparation и query, исходный prompt round-trip, fit-only demos, отсутствие
текущего dev gold в промпте, отдельный кеш повторов, запрет teacher, защита от
чужой маски, парный отчёт/выбор только после трёх повторов, partial IO recovery
и ограниченные внешние перезапуски. В тестах БД/API подменены; новые сетевые
соединения заблокированы. Windows launcher проверен целиком с `--dry-run`,
без SSH/генерации. Живой schema preflight выполнится при ручном запуске.

Выборка dev уже просматривалась на прежних этапах, поэтому результат будет
ретроспективным development-замером. Он не доказывает независимый перенос или
максимум среди всех масок. Следующий шаг после dev — контрольный запуск
выбранного compact-промпта на большом BIRD и обновление train utility-меток
перед улучшением классификатора. Автоматического внедрения промпта нет.
