# Расширение train и контрольные повторы — 10.11.2026

**Обновление 11.11.2026:** после [исправлений безопасности AUD-001/003/006](../src/adv_text2sql/sql_safety.py)
изменились закреплённые исходники. Приведённые ниже команды платных запусков
по старому манифесту теперь должны остановиться на проверке SHA. Перед запуском
18 повторов нужна новая версия протокола; исходный состав 644 оценок, inventory,
результаты и прежние манифесты сохранены.

**Schema inventory выполнен пользователем, платные запуски этапа не выполнялись.**
Из пилота 120/40 структурную проверку прошли **111 вопросов по 37 БД**;
девять вопросов отложены из-за пустой или несовпадающей схемы. Аудит источников
и отдельная очередь повторов существующего train готовы. Новые utility-метки
и модели не созданы.
Прежние train/dev/test и данные v2 сохранены. Причина этапа — отсутствие
устойчивого выигрыша в [экспериментах классификатора](25_classifier_refresh.md).

curated-версии строки. Вместе с кандидатами строятся компоненты по БД,
нормализованным семействам и консервативным near-duplicate-связям. Связанный
с dev/test кандидатный компонент блокируется целиком. Старые назначения
и group ID не меняются. Новый ID содержит benchmark и hash входа: одинаковый
числовой question_id в разных файлах не означает один вопрос. Повторяющиеся
входы внутри источника требуют разбора вместо молчаливого объединения эталонов.

## Первый ручной шаг: проверить новые БД Ambrosia

Выбран фиксированный пилот **120 вопросов по 40 новым БД**, по три на БД.
Детерминированный hash-отбор с seed=42 не использует правильность ответов модели
или SQL-эталон. Служебные категории нужны только для разнообразия выборки:

| Категория | Вопросов | БД |
| --- | ---: | ---: |
| Attachment | 42 | 14 |
| Scope | 39 | 13 |
| Vague | 39 | 13 |
| **Всего** | **120** | **40** |

Пилот содержит 36 неоднозначных вопросов и 40 кандидатных компонентов.
Это описание выбранного состава. Категории и ID не становятся признаками модели.
Файл — [`ambrosia_pilot.json`](../research_results/classifier_data_expansion_20261110/ambrosia_pilot.json).

**Проверка схем без LLM:**

```powershell
& "C:\Program Files\Git\bin\bash.exe" local/run_classifier_data_stage.sh --snapshot
```

Launcher поднимает управляемый SSH-туннель. Используется локальный `.env.deepseek`.
Python проверяет наличие выбранных БД через каталог PostgreSQL из известной
проектной БД, затем читает таблицы, колонки и типы в read-only-транзакциях.
Полный список серверных БД не сохраняется. Эталонные SQL и все альтернативы
неоднозначных вопросов только разбираются SQLGlot и сверяются с именами объектов:
**SQL-эталоны не исполняются, вызовов LLM нет**.

Результат — `schema_inventory.json`. Отсутствующие БД, пустые схемы, mismatch
и неразрешённые ссылки остаются явными ограничениями. Разрыв соединения
останавливает проверку с типом ошибки без пароля/DSN в сообщении. Готовый inventory
не перезаписывается; для другого снимка нужна новая папка этапа.
Согласованность имён не доказывает правильность исполнения эталона.

После inventory требуется **отдельный** сбор конфигураций новых train-вопросов.
Его платный запуск пока не подготовлен. Структурная проверка сама по себе не
создаёт наблюдений полезности и не делает набор готовым для обучения.

## Контрольные повторы существующего train

Очередь использует frozen-модель, промпты, схемы, evaluator и masks v2.
Первый сохранённый исход остаётся pass 1. Passes 2/3 имеют разные job-папки
и генерируют свежие ответы. Продолжение берёт checkpoint только своего прохода.
В каждом проходе одинаковые вопросы оцениваются всеми профилями своей задачи.

| Задача | Отбор | Уникальных вопросов | Профилей | Новых проходов | Новых оценок |
| --- | --- | ---: | ---: | ---: | ---: |
| BIRD | 26 различающихся + 8 agreement-controls | 34 | 5 | 2 | **340** |
| Ambrosia | 29 различающихся и 6 нестабильных: объединение 30; ещё 8 controls | 38 | 4 | 2 | **304** |
| **Всего** | Только train, без dev/test | **72** | — | **2** | **644** |

Controls выбираются из одинаковых исходов профилей с распределением по группам
и успехам/ошибкам, где они доступны. Отбор диагностический и зависит от прежних
train-исходов: качество этой подвыборки не является EX всего train/full/test.

Профили BIRD: ∅, 14+32, 14+32+35, 2+14+32+35, 2+7+14+32+35;
Ambrosia: ∅, 14, 14+32, 14+32+35. Всего **18 job** — девять профилей × два прохода.

| Оценка / ограничение | Значение |
| --- | ---: |
| Токены по исходному usage этих же точек | **2 024 818** |
| Ориентир времени при сходной скорости API | Около 1,5–2 часов, с запасом на preflight |
| Per-job caps | 80 примеров, 200 task calls, 1 млн токенов, 2 часа active time |
| Общие caps | 1000 примеров, 2500 task calls, 8 млн токенов, 6 часов active time |
| Teacher calls | **0** |

Caps — защитные пределы, не прогноз списания. `repeat_report.json` показывает
каждый исход, средние по наблюдаемым passes и парную разность с опорой.
Число парных проходов указано явно. Лучший ответ из трёх не выбирается,
старые метки не подменяются и новый датасет автоматически не экспортируется.

Очередь без SSH/БД/API:

```powershell
& "C:\Program Files\Git\bin\bash.exe" local/run_classifier_data_stage.sh --dry-run --max-jobs 18
```

Первый небольшой **платный** job повторов:

```powershell
& "C:\Program Files\Git\bin\bash.exe" local/run_classifier_data_stage.sh --run --repeat 2 --benchmark bird --configuration baseline --max-jobs 1
```

Вся серия, включая продолжение checkpoints:

```powershell
& "C:\Program Files\Git\bin\bash.exe" local/run_classifier_data_stage.sh --run --max-jobs 18
```

Только пересчёт отчёта сохранённых проходов:

```powershell
& "C:\Program Files\Git\bin\bash.exe" local/run_classifier_data_stage.sh --export
```

Незакрытый API-reservation блокирует job. Schema/reference preflight выполняется
до оплачиваемой генерации. Инфраструктурные ошибки не становятся отрицательными
метками; невалидный SQL модели остаётся исходом 0.

## Реализация и воспроизведение

Артефакты: `source_audit.json`, `candidate_questions.json`, `ambrosia_pilot.json`,
`summary.md`, `repeats/experiment.json`, `repeats/repeat_report.json` в
[`classifier_data_expansion_20261110/`](../research_results/classifier_data_expansion_20261110/).
После ручных запусков появятся `schema_inventory.json` и `repeats/jobs/`.
Источники и runtime закреплены SHA; схема и протокол прежней v2 не изменены.

Код: [prepare_classifier_data_stage.py](../scripts/prepare_classifier_data_stage.py),
[classifier_data_stage.py](../scripts/classifier_data_stage.py),
[run_classifier_data_stage.sh](../local/run_classifier_data_stage.sh).
**11 новых тестов** проверяют namespace, DB/family/bridge-защиту, train-only отбор,
пилот, схемы, среднее вместо best-of, свежие passes и resume своего checkpoint.
Ruff, Bash syntax и offline dry-run пройдены. При подготовке **0 LLM/DB/SSH-вызовов**.

Подготовить ещё одну версию в новую папку:

```powershell
& "C:\Program Files\Git\bin\bash.exe" local/run_classifier_data_stage.sh --prepare --output research_results/classifier_data_expansion_repeat
```

После inventory и повторов фиксируем результаты и решаем о сборе новых меток.
Прежние dev/test не переводим в train.
